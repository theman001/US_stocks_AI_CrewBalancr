## Round 2 — 0건

### 검토했으나 finding 아님 / 의도된 설계
- **situation 벡터를 기록 시가 아니라 backfill 시 생성** — §5.1 은 "기록 시"를 명시하나,
  (a) `situation_text` 는 기록 후 불변이라 언제 임베딩해도 동일, (b) 회상 자격은
  `rag_status ∈ {auto, approved}` (채점+게이트 후, 수 주 뒤)이므로 기록 시점엔 어차피
  회상 불가, (c) 주간 크루 실행 중 bge-m3(2.3GB) 로드 회피. → 주간 RAG 배치에서 일괄.
- **`evaluated` (채점됐으나 미반성) 항목 미색인** — `_INDEXED_STATUS = {reflected, gated}`.
  no-LLM 림보 상태(reviewer 가 rag_status 는 정했으나 status=evaluated)는 DeepSeek 잔액
  충전 후 reflected/gated 로 이동하며 색인됨. 반쪽 상태 도입 대신 보수적 제외.
- **`backfill()` 예외 미포획** — evaluate/reviewer 는 항목별 스킵하나 임베딩은 배치 단위
  all-or-nothing 이고 bge-m3 실패는 조용히 넘길 게 아닌 실 장애 → cron 실패로 표면화 의도.
- **`get_or_create_collection(metadata=cosine)`** — 기존 컬렉션엔 무시됨 (get 경로).
  신규 배포는 항상 cosine space 로 생성.
- **metadata 빈 문자열 값** (`sleeve: ""` 등) — ChromaDB 1.1.1 수용 확인 (테스트 통과).
- `_client` lru_cache(maxsize=4) — 프로덕션은 단일 경로. 테스트는 경로별 캐시 + fixture
  `cache_clear`.
